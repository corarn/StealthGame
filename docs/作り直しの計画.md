## 1サイクルの型

```
① 質問：自分で「このステップで何を作るか・何がわからないか」を書く
② 解説：AI に考え方を図か数字で説明してもらう。決めるところは選択肢とおすすめを出してもらう
③ 実行：自分で Mermaid で図を描く → AI に見てもらう
        → コードを書く → ビルド → 画面で確認 → コミット
④ 振り返り：devlog に書く
        ・わかったこと／わからなかったこと
        ・図と実際のコードの違い
        ・このステップは 4つの視点（下）のどれだったか、1行で
```

1サイクル＝ビルドして画面で確かめられる大きさ。

### 4つの視点（振り返りで1行だけ使う）
| 視点 | 一言 | 今の段階でのブレーキ |
|---|---|---|
| ① できないことをできるようにする | まず動かす | YAGNI・KISS（先回りして作らない・単純に） |
| ② 汎用化する | 同じものが2〜3回出たら、まとめる | DRY・SRP（1クラス1責務） |
| ③ 便利にする | 使う側の手間を減らす | 最小驚きの原則 |
| ④ 一般化する | 共通の形を親クラスにする | DIP・LSP |

- 作り直しの前半は、ほとんど ①。②〜④ は「同じものが実際に2つ以上出てきてから」
- 根拠：「Make it work, make it right, make it fast」（Kent Beck に帰されることが多い。最初に言った人ははっきりしない）、「3回目でまとめる（Rule of Three）」（Don Roberts の言葉。Fowler『リファクタリング』1999 で広まった）
- 4つの視点そのものは、1つの決まった理論ではない（元の資料にもそう書いてある）
